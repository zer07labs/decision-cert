# Contributing to decision-cert

This repository holds a frozen specification, a reference verifier and the fixtures that bind every
other implementation to it. Changes are small and reviewed closely.

## Ground rules

- **The v1 spec is frozen.** `spec/decision-certificate.v1.md` and
  `spec/decision-certificate.v1.schema.json` do not change. A change to any field or its meaning is
  `decision-certificate.v2`. A correction is a dated note or an entry in `spec/ERRATA.md`, never an
  edit of the frozen text.
- **Fixtures are never hand-edited.** They are generated by a program and shared byte for byte with
  other repositories. A fixture change regenerates the file and updates every copy in one change.
- **The Rust crate is the reference verifier.** A verifier in another language that disagrees with
  it on a fixture is wrong until an erratum says otherwise.
- **Wording.** A certificate describes a measured process; it never promises an outcome. Names, docs
  and messages make no promise about outcomes. CI checks `spec/`, `docs/` and the top-level docs
  for this.
- **No data.** No customer data, no model outputs, no private keys. Fixtures carry public keys and
  deterministic test signatures only.
- **Everything here is public**, commit messages included.

## Workflow

- Branch from `main`, one change per branch, open a pull request.
- CI must pass: `rust` (fmt, clippy, tests, the conformance fixtures, `cargo deny`) and the other
  jobs in `.github/workflows/ci.yml`.
- **Merge with a merge commit, never squash.** This overrides the zer07labs organisation default
  (squash): the history of a spec and its fixtures is kept commit by commit.

## Local checks

```bash
cd rust && cargo fmt --check && cargo clippy --all-targets -- -D warnings && cargo test
cd rust && cargo deny check
```

## Reporting a vulnerability

Not in a public issue. See [`SECURITY.md`](SECURITY.md).
