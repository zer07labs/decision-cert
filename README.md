# decision-cert

The open specification for **decision certificates** (`decision-certificate.v1`), a Rust crate that
verifies and applies them, and the conformance fixtures every implementation must agree on.

## What a decision certificate is

A decision certificate is a signed record of how one model's answers to one decision were measured:
the labelled calibration cases, the threshold chosen, the share of cases it answers, and a bound on
the error of the answered cases at a stated confidence. It is signed (Ed25519 over the JCS bytes) by
whoever ran the measurement, and its id is `sha256:` of those bytes.

**Certificates describe a measured process, never guarantee an outcome.** The bound holds only
while future cases are exchangeable with the calibration cases; it says nothing about any single
decision, about label quality or fairness, or about populations that were never sampled. That is
why certificates expire. [`docs/certificates.md`](docs/certificates.md) lists what a certificate
claims and what it does not.

## Layout

| Path | What |
|---|---|
| [`spec/`](spec/) | `decision-certificate.v1.md` (normative, **frozen** 2026-10-25) and its JSON Schema |
| [`rust/`](rust/) | the `decision-cert` crate: `verify`, `canonical`, `certificate_id`, segment thresholds, expiry |
| [`fixtures/`](fixtures/) | conformance fixtures: signed certificates with their JCS bytes, ids and expected verdicts, plus `mutations/schema_invalid.json`, schema-invalid certificates a verifier must reject |
| [`docs/certificates.md`](docs/certificates.md) | how to issue, verify and apply a certificate |

v1 is frozen: any change to a field or its meaning is `decision-certificate.v2`, and v1 verifiers
reject unknown fields. The spec's "reference implementations" line still names the paths these
files had in `zer07labs/decisiond` (`server/crates/decision-cert` is now `rust/`,
`tests/fixtures/cert_conformance/` is now `fixtures/`); the spec text is left byte-for-byte as frozen.

## Using the crate

Not on crates.io yet. Pin a git revision:

```toml
decision-cert = { git = "https://github.com/zer07labs/decision-cert", rev = "<sha>", version = "0.1.0" }
```

```bash
cd rust && cargo test     # unit tests + the conformance suite over ../fixtures
```

## The Python issuer

The issuer (`dk certify`, `certify.py`, `certify_stats.py`) and the recalibrator (`dr`, `recal.py`)
still live in `zer07labs/decisiond`, where they are locked while that repo's Phase A experiments run.
They move here, as a Python package, after Phase A's Q14 verdict. Until then the fixtures in
`fixtures/` are generated by decisiond's `py/tests/test_cert_conformance.py` and copied here; a
fixture change lands in both places in the same change.
